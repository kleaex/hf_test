# 検証手順

## 自動公開・運営承認モード

- 自動公開の本文再構築はEventSettings・Users・Memberships・Exhibitorsを各1回読み、Sessionsを必要としない。共有キャッシュ命中時はシート読取0回。

`tests/publication-mode.test.mjs` で以下を確認する（ローカルの代替サービス・最小DOM）。

- 既存の未設定環境は運営承認で、従来の公開対象を維持する。
- 自動公開で既存・新規OTP登録を掲載し、承認モードに戻すと以前の承認状態を使う。
- OTP未確認・登録途中・利用停止・所属解除・別開催回は自動掲載しない。登録途中に作られたキャッシュも最終確定後は更新される。
- 承認後のプロフィール・作品は再承認なしで更新できる。モード変更は本文と画像のキャッシュを失効させる。
- 運営以外の変更、不正モード・競合・要求IDの流用を拒否する。旧画面からモード省略で保存しても現在値を維持する。
- 出店11組のライブカタログと運営設定を扱える。HP・旧GASの管理画面でモード保存・承認欄の無効化・再読込を確認する。

ブラウザー描画・実GAS・Pagesでの確認は未実施。配置と実環境の受入確認はSETUP.md先頭を参照する。

## 公開本文の直接取得

- 公開GETは既存の公開APIだけを呼び、非公開フィールド・画像本体・認証情報を返さない。任意method・tokenで操作を変更できない。
- 不許可originと任意コードを含むcallbackを拒否し、正本を読まない。紹介文のscript終了文字等はコードとして実行されない。
- HPはiframeを作らず本文を受け取り、callback・script・タイマーを解放する。遅い応答は削除済みcallbackを呼ばない。
- 同時取得は1回にまとめ、次回取得は新しく読み直す。
- 通信失敗・callbackなしの旧GAS・不正応答・タイムアウトは従来経路へ戻る。正本のエラーは別経路で隠さない。
- 本人・運営の既存通信の検証を維持する。

上記は実コード・代替Googleサービス・最小DOMで検証。実GoogleのJavaScript応答、リダイレクト、画像の後続接続と速度はSETUP.md冒頭に従い配置後に確認する。
本文のcatalogTextReadyと、後続画像のbridge時間を足し合わせない。

## カタログ初回表示の通信統合

- 初回の公開カタログをGASの接続完了通知から受け取り、追加のカタログRPCを送らず表示できる。
- origin・iframeの所属・nonceの異なる初期応答は受け取らない。初期応答のエラーを成功扱いにしない。
- 非公開情報・Drive ID・内部メモを含めず、script終了文字・Unicode区切り文字等を安全にJSONへ埋め込む。
- 後から行う取得では初期応答を再利用し続けず、保存後の現在の状態を読む。
- 旧GAS・先に別APIで接続した場合にも従来公開APIへ戻れる。
- 画像付きカタログでも初期応答ではDrive API・DriveAppの確認／読取を行わず、本文だけを返す。Drive障害でも本文を返す。
- HPは本文のDOMを作成してから画像を通常取得し、追加のカタログRPCを送らない。
- 段階更新時の旧GASの同梱画像は互換処理で表示できる。カタログに属さない画像・不正画像は通常取得へ戻る。

上記は実コードと代替サービス／最小DOMで検証する。実環境ではSETUP.md冒頭に従い、初回ページ読込時のcatalogInitial・catalogLoad・catalogTextReadyを計測する。
画像単体の計測値や接続済みAPIの約1秒を、ページ初期表示の時間と混同しない。

## 画像表示・登録の計測

- 明示実行する画像計測は公開画像1点の一覧用・拡大用を各2回だけ取得し、保存・削除・共有変更を呼ばない。
- 復号に使ったBlob URLを成功・失敗ともに解放する。画像なし・復号失敗・非対応を正常値として返さない。
- 出力は固定した処理名・時間・容量・種類・回数のみ。画像本体・名前・画像ID・Drive ID／URL・認証情報・任意フィールドを含めない。
- 通常の表示でもメモリー・進行中要求の共有・ブラウザー保存・GAS取得を区別し、重複取得を増やさない。
- 取得待機列とBase64展開を記録し、ブラウザーのdecode()完了を画像の表示準備として扱う。実描画完了の証明にはしない。
- 編集画面のプレビュー保持と登録の同一要求再送を維持し、調整前後の容量・主画像の圧縮試行回数・仮保存成功までの時間を記録する。

実環境の値はSETUP.md先頭の手順で採取する。模擬DOMは実画像の復号・画質・体感速度を証明しない。

## 共有キャッシュの再構築が続く場合の診断

- 小さいカタログは1項目で保存し、次の取得では命中する。旧分割形式と大きいUnicodeデータも維持する。
- 保存失敗・読取失敗・保存直後の消失を固定した診断コードで区別する。
- HF_PERFORMANCE有効時だけ保存直後の読取確認を行い、無効時は追加の確認読取を行わない。
- ブラウザーへ渡す診断は許可したコードと回数だけ。キャッシュキー・内容・生の例外・任意フィールドを含めない。
- いずれのキャッシュ障害でも正本表示を継続し、保存時の世代変更による無効化を維持する。

実環境の原因確定には、SETUP.md冒頭の同一ページで連続2回取得したログを使う。模擬キャッシュの成功を実GASの保持保証として扱わない。

## カタログ・登録速度とプレビューの改善（今回）

- カタログ10組を、設定・出店者シートの一括読取2回で構築する。共有キャッシュ命中時はSheets読取0回。
- アプリの保存・非公開化でキャッシュ世代を変更し、保存後の取得で旧版を返さない。
- キャッシュの部分消失・期限切れ・障害・Unicodeを含む分割を扱い、正本に戻れる。
- 世代変更失敗なら保存前に停止。Sheets書込失敗・書込後の応答喪失でもキャッシュの整合性と同一要求再送を保つ。
- 共有小画像は公開判定・Driveの非公開状態・保存先・更新日時と内容の検証を通す。非公開化・共有変更・改変を拒否。
- 変換・Drive保存中は共通ロックを保持せず、他のカタログ取得を進められる。同じ出店者の二重アップロードは予約で拒否。
- 変換中の別画面保存・ログアウト・停止・締切変更を最終確定で検出し、未確定の画像を公開しない。
- 仮保存・最終保存でプレビューを消さず、同じ画像を取り直さない。再読込時は本人用小画像を自動表示。
- JPEG入力でPNG圧縮を先に試さず、新規小画像のCanvasを長辺240px以内にする。実ブラウザーの画質は別途確認。
- 最初の代表画像2点を単独で先行取得し、待機中の一覧より拡大要求を優先する。
- 計測応答は固定した区間名・時間・回数のみ。入力・メール・画像・ID・URL・トークンを含めない。

全試験は `node --test tests/*.test.mjs`。実GASの秒数・Googleの画像変換・ブラウザー表示は模擬環境では証明しない。
実環境ではSETUP.md冒頭の手順で反映し、HF_PERFORMANCEを有効にして初回／再表示／登録の時間を区別する。

- 一覧と拡大を別に扱い、クリックした拡大要求を未取得の一覧要求より先に処理する。

## HP内の操作・保存後の自動反映（今回の受入条件）

配置手順はSETUP.md冒頭を使う。下記はローカルの代替サービス／最小DOMでは確認済み、実GAS・Pagesでは未確認。

- 公開・出店者・運営画面の操作、画像拡大と閉じるまでHPのURLに留まる。
- 非表示iframeから、許可したHP origin・最上位windowの要求だけを受け付ける。
- HP側では正しいiframeの子孫・Google origin・nonce・要求IDだけを受け付ける。
  別窓・偽origin・古いnonce・重複応答・未知の要求を受理しない。
- 不正な接続URL・未設定を拒否。ready前・タイムアウト・Googleエラーを保存成功にしない。
- 本人・運営の認証、期限、競合、同一要求再送の既存条件を維持する。
- 仮保存時点では公開状態が変わらず、最終保存で文章・作品・画像参照が揃って反映される。
- 新規作品にも画像を仮保存して、最終保存1回で作品と画像を作成できる。

- サムネイルの形式・寸法・容量をサーバーで検証する。最終保存時は1作品3点を検証する。
- 来場者のログインなしで公開対象だけを取得でき、未選択・仮保存・削除済み画像は取得不可。
- メール・認証・内部メモ・Drive ID／URL・保存先情報を公開応答に含めない。
- 運営の設定保存・非公開化は次回読込から反映。対象0組も正常表示する。

## 本人限定保存の合格条件（コード実装済み・実環境で一部確認済み）
- 保存・再読込後にプロフィールと複数頒布物が一致する。
- 他者のプロフィール・作品の読取（非公開部分）・更新・削除を拒否する。
- 無効・期限切れ・失効したセッションで編集できない。
- 古い画面の保存は競合として拒否し、既存内容を変えない。
- 同じ保存要求の再送で更新番号や新規頒布物を二重に作らない。
- 同じ要求IDに別内容を載せた操作を拒否する。
- コード再利用・期限切れ・5回誤入力・再送前のコード・宛先変更後の旧コードを拒否する。
- 新規登録は任意の有効なメールに送信し、OTP確認前は確定しない。ログイン時は未登録メールへ送信せず、再送間隔・回数制限を守る。
- メール失敗やGoogle割当不足で、既存プロフィールやログイン情報を壊さない。
- ソース、Sheets、ログ、ブラウザーURLにコード・セッショントークンの原文を残さない。
  コード原文は送信メールと利用者の入力欄、トークンはログイン応答・ブラウザーのメモリー・
  同じタブの復元用sessionStorageに必要。localStorageには保存しない。
- 再読み込み後はGASの検証成功後にだけ編集画面を開き、未保存入力を復元しない。
- 再読み込みで絶対期限を延長せず、期限切れ・失効・所属解除なら再ログインを案内する。
- ログアウト成功で一時保存を削除し、再読み込みでログイン状態に戻らない。
- 復元時の通信失敗では一時保存を維持して再試行でき、Storage拒否時もログイン・保存を利用できる。

## 手動公開の合格条件（コード実装済み・実環境未検証）
- 公開JSONを許可項目で生成し、非公開情報の混入を検出する。
- 明示した出店者だけを含み、ブースが空の場合は配置未定になる。
- 元Driveファイルや書き出しフォルダを公開せず、画像のコピーをZIPへ含める。
- 画像欠落・改変・不正参照・余分な私的ファイル・共有画像・不正設定を拒否する。
- 確認用作成ではdocs/を変更せず、適用時は全画像の配置成功後に現行データを切り替える。
- 取り込み時の失敗や同一版IDの内容衝突では、現行データを切り替えない。
- 保存済み旧版へ切り戻せ、公開画面の版ID・画像・検索・補足画像を確認できる。
- 実GASのZIPを展開して取り込み、Pages反映後の版ID・画像を確認する。

## 画像・編集期間の合格条件（コード実装済み・実環境未検証）

- JPEG・PNG・GIF・BMPを選択し、向き・縦横比を保ってプレビューできる。GIFは静止画になる。
- 線画・本文・透過PNG・スマホの回転付きJPEGで、縮小後の文字や背景を確認する。
- 元画像20MB・6,000万画素を超えるもの、非対応形式・破損画像を拒否する。
- 送信画像がJPEG/PNG・長辺2,400px・1.5MB以内になる。調整後のプレビュー確認なしでは登録しない。
- 1作品3点まで。登録・再読込・表示・削除・順序変更・差替えが本人の作品だけに適用される。
- 別の出店者／別作品の画像IDを指定した取得・紐付けを拒否する。Drive ID・内部ハッシュを画面に返さない。
- 公開／共有フォルダや共有ファイルを拒否する。専用フォルダと画像を出店者に共有しない。
- 画像追加前に作品を保存する。画像登録は即時保存、画像削除・並べ替えはプロフィール保存で確定する。
- Drive作成後にSheets書込が失敗しても、同一要求の再送でファイル・画像登録を重複作成しない。
- 編集期限の未設定・不正・終了済みをGASでも拒否し、閲覧と確定済み要求の結果確認だけを許可する。
- 削除した画像は本人の取得APIから読めなくなる。Drive上には保持され、自動物理削除しない。
- GoogleのBlob.getAsによる実変換と変換割当の扱いを確認する。

## ブラウザーの模擬環境

`node tests/serve-experiment.mjs` で http://127.0.0.1:8081/ を開く。
宛先 `a@example.invalid` / `b@example.invalid` の模擬コードが画面上部に出る。
運営画面は http://127.0.0.1:8081/?view=admin 、運営宛先は `ops@example.invalid` 。
上部の「次の保存応答を失わせる」で、保存成功後の通信失敗からの再送を試せる。
これは実験用本体には含まれないローカル検証用の仕組み。

確認する操作:
1. 接続確認 → コード送信 → コード入力 → ログイン。
2. 出店名・紹介文・頒布物2点を入力し保存。再読込で一致する。
3. 1点を編集し、もう1点を削除して保存。再読込で確認する。
4. 応答喪失を設定して保存。入力が固定され、同じ要求の再送で1回だけ保存される。
5. 未保存のまま読直し・ログアウトすると確認が出る。ログアウト後は編集内容を表示しない。
6. A・Bを別のブラウザーで操作し、内容が分離している。幅390pxでも入力・保存できる。
7. HTMLとして解釈される文字列を紹介文に入れてもスクリプト実行や要素追加が起きない。
8. ログイン・保存後にブラウザーを再読み込みし、コード再送なしで保存済み内容を表示する。
9. ログアウト後の再読み込みではログイン画面になる。復元時に失効が判明した場合も同様。

## 運営画面の実環境合格条件

- /exec?view=adminで運営ログイン画面が開き、出店者トークンや出店者用コードで運営APIを利用できない。
- 出店者登録のない運営の専用宛先で、コード送信・確認・1時間セッション・再読み込み復元・ログアウトを確認する。
- 初期登録で旧公開設定と編集期限を移行し、再実行で変更済み設定・出店者データを上書きしない。
- 開催日・会場・編集期限・配置・公開対象を画面から保存できる。旧Script Propertiesの公開設定は運用値に影響しない。
- 期限の空欄・終了が出店者の編集拒否に反映され、運営による再開操作が明示される。
- 古い設定更新番号・重複ブース・不正項目・別開催回の指定を拒否する。
- 公開内容の確認後に出店者情報または設定を変えると、書き出し前に再確認を必要とする。
- プレビューは10分で失効し、別運営がプレビューを作ると前の確認が置き換わる。
- 書き出しの応答喪失時に同じ要求で再試行でき、ZIPと履歴を重複作成しない。
- 運営停止・許可宛先除外・セッション失効が各APIへ反映される。
- 所有者のGoogleアカウントでDriveリンクからZIPを取得できる。共有設定が自動変更されない。
- 直近20件の履歴は「書き出し履歴」であり、Pagesへの配信完了と混同しない。
